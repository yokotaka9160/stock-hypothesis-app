# Feature Specification: 株式取引 仮説検証

**Feature Branch**: `001-hypothesis-verification`（仮）
**Created**: 2026-10-30
**Status**: Draft
**Input**: 米国株の売買仮説を保存し、過去データでのシミュレーション検証結果と仮説の問題点を表示する

## Clarifications

### Session 2026-10-30

- Q: 仮説の「問題点」は、どういう基準で判断して表示するか？ → A: 決まったルールで判定する。損益の正負にかかわらず毎回判定し、損益がマイナスのときはその原因もあわせて表示する
- Q: 検証にはどの細かさの株価データを使うか？ → A: 1分足（市場前・市場後を含む）
- Q: 逆指値の注文は、1分足のどの時点で、いくらで約定したものとして計算するか？ → A: 高値が逆指値価格に届いた最初の足で、逆指値価格で約定。その足の始値がすでに逆指値価格を上回っていた場合は始値で約定
- Q: 購入金額から株数をどう決め、手数料を損益に含めるか？ → A: 購入金額÷約定価格の端数を切り捨てた整数株。手数料は含めない。1株も買えない場合は購入しなかったものとして扱う
- Q: 決算発表の正確な時刻が分からない場合、「決算発表時刻の5分前」はどう扱うか？ → A: 区分から時刻を決め打ちする。市場前の発表は 8:00、市場後の発表は 16:00（いずれも米国東部時間）とみなす
- Q: 仮説は、どのような形で入力するか？ → A: 自由な文章で入力し、システムがシミュレーション可能な条件に変換する
- Q: 「市場終了時」「市場前の終了直前」に全売却するとき、どの1分足のどの価格で売れたものとするか？ → A: その時間帯の最後の1分足の終値（市場終了時は 15:59 の足、市場前の終了直前は 9:29 の足。米国東部時間）
- Q: 逆指値の価格にすぐ届かない場合、注文はいつまで有効とするか？ → A: トリガーから決まった時間まで。有効時間は仮説の文章で指定でき、指定がなければ60分とする
- Q: 株を保有している間に、同じ銘柄で再びトリガー条件が成立した場合、新しく買うか？ → A: トリガー成立時に資金上限（購入金額）まで購入し、その後は売却するまでトリガーを無視して、売却条件にしたがって売却する
- Q: 「市場前」「市場中」「市場後」は、それぞれ何時から何時までとするか？ → A: 市場前 4:00〜9:30、市場中 9:30〜16:00、市場後 16:00〜20:00（米国東部時間）。市場前の購入は同日 9:29、市場後の購入は翌営業日 9:29 に売却

## User Scenarios & Testing

### User Story 1 - 仮説の保存・編集・削除 (Priority: P1)（仮）

利用者は、売買の仮説を入力して保存する。保存した仮説は、アプリを閉じて開き直しても残っている。保存した仮説は、後から編集・削除できる。

**Why this priority**: 仮説が保存できないと、検証も問題点の提示も行えないため。（仮）

**Independent Test**: 仮説を保存し、アプリを再起動したあとも同じ内容で表示されることを確かめる。

**Acceptance Scenarios**:
1. **Given** 仮説の入力欄が空の状態で、**When** トリガー条件・購入条件・購入方法・売却条件を含む仮説を文章で入力すると、**Then** 変換された条件が表示され、利用者が確認して [保存] を押すと、画面の左セクションに仮説が保存・表示される。
2. **Given** 仮説が保存されている状態で、**When** アプリを閉じて開き直すと、**Then** 保存した仮説が同じ内容で表示される。
3. **Given** 仮説が保存されている状態で、**When** 仮説を編集して保存すると、**Then** 編集後の内容が表示される。
4. **Given** 仮説が保存されている状態で、**When** 仮説を削除すると、**Then** その仮説は表示されなくなる。

---

### User Story 2 - シミュレーション検証結果の表示 (Priority: P1)（仮）

利用者は、保存した仮説について銘柄・期間・購入金額を指定して [検証] を押し、過去データでのシミュレーション結果を確認する。

**Why this priority**: このサービスの中心となる機能であるため。（仮）

**Independent Test**: 同じ仮説・同じ条件で2回検証し、結果が完全に一致することを確かめる（constitution 原則I・IV）。

**Acceptance Scenarios**:
1. **Given** 次の仮説が保存されている状態で、
   - トリガー条件：第1四半期の決算発表時刻の5分前になったとき
   - 購入条件：その時点の価格から4%上昇した価格
   - 購入方法：逆指値
   - 売却条件：購入が市場前または市場後の場合は、市場前の終了直前に全売却。購入が市場中の場合は、市場終了時に全売却

   **When** 銘柄・検証期間・購入金額を指定して [検証] を押すと、
   **Then** 画面の右セクションに、検証した仮説・検証期間・総取引回数・損益額が表示される。
2. **Given** 複数の銘柄を選んだ状態で、**When** [検証] を押すと、**Then** 銘柄ごとの結果と、全銘柄合計の結果の両方が表示される。
3. **Given** 逆指値の価格に届かなかった場合、**When** 検証が行われると、**Then** その回は購入しなかったものとして結果に反映される。

---

### User Story 3 - 仮説の問題点の提示 (Priority: P2)（仮）

利用者は、検証結果とあわせて、仮説の問題点を確認する。

**Why this priority**: 検証結果を信頼して判断に使うために必要だが、検証結果がないと提示できないため。（仮）

**Independent Test**: 検証を実行し、問題点が左セクションの検証仮説の下に表示されることを確かめる。

**Acceptance Scenarios**:
1. **Given** 仮説の検証を実行した状態で、**When** 検証結果が表示されると、**Then** 左セクションの検証仮説の下に、次の観点からの問題点が表示される。
   - 取引を実行する時間帯
   - トリガー条件
   - トリガー条件の数値

---

### Edge Cases

- 入力した文章をシミュレーション可能な条件に変換できない場合（項目が足りない・意味が曖昧など） → 変換できなかった項目を示し、文章の修正を求める。保存はしない
- 逆指値の価格に、注文の有効時間内に届かず購入されなかった場合 → 購入しなかったものとして結果に反映する
- 注文の有効時間がその日の市場後の終わり（20:00、米国東部時間）を超える場合 → 20:00 で注文を打ち切る
- 検証期間内に、データが取れない銘柄や日があった場合 → 銘柄の全日データが取れなければ検証不可として表示、一部の日にちがデータを取れない場合はその日のデータは無しとして検証続行
- 購入金額が約定価格に満たず、1株も買えない場合 → 購入しなかったものとして結果に反映する
- 決算発表の正確な時刻が取得できない場合 → 市場前の発表は 8:00、市場後の発表は 16:00（米国東部時間）とみなして検証する
- 保有中に同じ銘柄で再びトリガー条件が成立した場合 → 買い増しせず無視し、売却条件にしたがって売却する
- 売却条件の「市場前の終了直前」は、市場前に購入した場合は同じ日の 9:29、市場後に購入した場合は翌営業日の 9:29（米国東部時間）の1分足を指す

## Requirements

### Functional Requirements

- **FR-001**: システムは、トリガー条件・購入条件・購入方法・売却条件からなる仮説を保存できなければならない。
- **FR-001a**: システムは、利用者が自由な文章で入力した仮説を、トリガー条件・購入条件・購入方法・売却条件の各項目からなるシミュレーション可能な条件に変換しなければならない。
- **FR-001b**: システムは、変換した条件を保存前に利用者に表示し、利用者が確認してから保存しなければならない。
- **FR-001c**: システムは、検証時に、保存済みの変換後の条件を用いなければならない（検証のたびに文章を変換し直してはならない）。
- **FR-002**: システムは、保存した仮説を、アプリを再起動しても保持しなければならない。
- **FR-003**: システムは、保存した仮説を編集・削除できなければならない。
- **FR-004**: システムは、検証時に銘柄（複数可）・検証期間・購入金額を指定できなければならない。
- **FR-004a**: システムは、1回の取引で買う株数を「購入金額 ÷ 約定価格」の端数を切り捨てた整数とし、損益額の計算に手数料を含めてはならない。
- **FR-004b**: システムは、1銘柄につき同時に1つの取引だけを扱わなければならない。トリガー成立後、注文の有効時間中または保有中に同じ銘柄で成立したトリガーは無視し、売却（または注文の打ち切り）後に次のトリガーを受け付ける。
- **FR-005**: システムは、対象を米国株としなければならない。
- **FR-006**: システムは、検証結果として、検証した仮説・検証期間・総取引回数・損益額を表示しなければならない。
- **FR-007**: システムは、複数銘柄の検証では、銘柄ごとの結果と全銘柄合計の結果を表示しなければならない。
- **FR-008**: システムは、トリガー成立から注文の有効時間内に逆指値の価格に届かなかった場合、購入しなかったものとして扱わなければならない。注文の有効時間は仮説の文章で指定でき、指定がない場合は60分とする。
- **FR-008a**: システムは、1分足の高値が逆指値価格以上になった最初の足で約定したものとし、約定価格は逆指値価格としなければならない。ただし、その足の始値がすでに逆指値価格を上回っていた場合は、始値を約定価格としなければならない。
- **FR-008b**: システムは、売却条件が「市場終了時」の場合は 15:59 の1分足の終値で、「市場前の終了直前」の場合は 9:29 の1分足の終値（いずれも米国東部時間）で、保有株をすべて売却したものとしなければならない。
- **FR-009**: システムは、データが取れない場合、検証不可として表示しなければならない。
- **FR-010**: システムは、検証結果の表示時に、損益の正負にかかわらず、仮説の問題点を時間帯・トリガー条件・トリガー条件の数値の観点から、次の決まったルールで判定して表示しなければならない。
  - **FR-010a（時間帯）**: 取引に市場前または市場後の取引が含まれる場合、流動性が低い時間帯であることを問題点として表示する。
  - **FR-010b（トリガー条件）**: 検証期間内のトリガー条件の成立回数が10回未満の場合、判断材料が足りないことを問題点として表示する。
  - **FR-010c（数値）**: 仮説の数値（例：購入条件の上昇率）を±1%・±2%ずらして再検証し、元の結果と損益の符号（プラス／マイナス）が変わるものがあれば、数値に過度に依存していることを問題点として表示する。
  - **FR-010d（損失の原因）**: 検証結果の損益がマイナスの場合、損益を時間帯（市場前／市場中／市場後）ごとに分けて表示し、損失が出た時間帯を原因として示す。
  - 問題点の判定は、同じ検証条件に対して常に同じ結果にならなければならない。
- **FR-011**: システムは、同じ条件の検証に対して、常に同じ結果を返さなければならない。
- **FR-012**: システムは、実際のお金を用いた取引を行ってはならない。
- **FR-013**: システムは、市場前・市場後を含む1分足の株価データを用いてシミュレーションしなければならない。トリガー条件の時刻判定と逆指値の約定判定は、1分足の単位で行う。
- **FR-014**: システムは、決算発表の正確な時刻が取得できない場合、発表の区分から時刻を決めなければならない。市場前の発表は 8:00、市場後の発表は 16:00（いずれも米国東部時間）とみなす。
- **FR-015**: システムは、時間帯を次のとおり区切らなければならない（米国東部時間）。市場前：4:00〜9:30、市場中：9:30〜16:00、市場後：16:00〜20:00。取引の時間帯は、約定した1分足の時刻で判定する。

### Key Entities

- **仮説**: 入力した文章、トリガー条件、購入条件、購入方法、注文の有効時間（指定なしは60分）、売却条件
- **検証条件**: 対象の仮説、銘柄（複数）、検証期間、購入金額
- **検証結果**: 検証条件、総取引回数、損益額（銘柄ごと・合計）、検証不可の情報
- **問題点**: 対象の検証結果、観点（時間帯／トリガー条件／数値）、内容

## Success Criteria

### Measurable Outcomes

- **SC-001**: 検証結果が正常に表示される。（検証不可以外のエラーが出ないこと）
- **SC-002**: 同じ条件で2回検証すると、結果が完全に一致する。（仮：constitution 原則I から）
